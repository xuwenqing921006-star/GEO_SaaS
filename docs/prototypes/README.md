## 已确认视觉方向

- 左上角使用深绿色品牌锚点，主体保持白色高密度工作区。
- 客户 GEO 证据轨道使用四段横向状态区，事实、内容、来源和 AI 可见性可独立判断。
- 表格、表单和诊断页减少无意义卡片，使用薄边框、紧凑行高和清晰分区。
- P05 使用真实编辑软件式结构：文档标题栏、编辑工具栏、正文画布、自动保存状态、内容简报和事实/推荐检查。
- 1440px 显示 P05 完整三栏；1280px 保留简报与编辑器，检查区进入抽屉；1024px 以编辑器为主，简报和检查均通过抽屉查看。
- 生图稿中的成立年份、年龄、地址、班额、人员经历和调研数值均视为无效占位，不进入 HTML 原型。

## 产品边界

- 唯一使用者为平台负责人，客户首版不登录。
- 服务对象为各类本地服务企业，少儿美术只作为当前演示行业。
- 首版采用代运营，不自动发布；平台负责人注册、维护可复用的运营账号并人工发布。
- 核心结果不是传统关键词排名，而是让企业在主流 AI 平台的相关问答中逐步实现：
  - L1 被发现；
  - L2 被正确理解；
  - L3 进入推荐候选；
  - L4 在核心问题中可重复出现。

## 关键操作路径

1. 在客户组合选择客户并进入企业知识库。
2. 补充企业事实与证据，处理冲突后进入 GEO 策略。
3. 根据 L1—L4 缺口生成内容计划。
4. 从问题簇和内容简报进入内容工作台。
5. 完成事实锁、推荐理由检查、自然化和最终复核。
6. 标记可导出后进入发布渠道。
7. 人工发布后创建 AI 监测批次，观察被发现、理解、推荐和重复出现情况。

## 关键组件

- 全局客户切换、搜索、后台任务入口。
- 客户 GEO 证据轨道：企业事实、内容覆盖、来源覆盖、AI 可见性。
- 行业通用知识库字段和可选行业模板。
- L1—L4 结果阶梯与诊断建议。
- 问题簇、关键词、文章类型、内容简报和优先级。
- 三栏内容编辑器、事实快照、证据缺口、禁用表达和推荐理由结构检查。
- 运营方渠道目录、内容匹配与渠道详情抽屉。
- 平台 × 问题 × 采集方式的监测结果表。
- 创建客户弹窗、事实/渠道详情抽屉、后台任务提示、保存提示。

## 状态覆盖

- 正常：完整业务数据。
- 加载：页面或后台任务加载中。
- 空白：新客户尚无资料、内容、渠道或监测数据。
- 错误：连接失败、局部数据失败或登录错误。
- 成功：保存、创建、导出或任务完成。
- 补充状态：资料待补全、事实冲突、证据不足、生成受阻、样本不足、连接正常。

## 演示数据结构

原型使用静态演示数据表达以下核心对象：

- `Client`：企业名称、地区、行业、状态、资料完整度、目标阶段。
- `Fact` / `Evidence`：事实值、确认状态、来源、更新时间、冲突关系。
- `QuestionCluster`：问题类型、用户问题、地区词、行业词、意图和目标阶段。
- `ContentBrief` / `ContentDraft`：题目、文章类型、必需事实、证据缺口、推荐理由、禁用表达、版本状态。
- `Channel` / `PublicationTask`：渠道、账号归属、收费方式、适合内容、发布准备状态。
- `MonitorBatch` / `MonitorSample`：平台、消费者页面或 API、问题、品牌/非品牌属性、L1—L4 结果、可见来源、采样时间。

## 生产接口位置

高保真 HTML 不调用真实接口。阶段 C 已将生产接口固定在以下业务动作：

- P00：负责人认证与会话。
- P01—P02：客户、资料上传、文本提取、事实、证据和冲突处理。
- P03—P04：GEO 诊断、问题簇、关键词和内容简报生成。
- P05：DeepSeek/通义千问生成、交叉检查、事实锁、自然化和版本保存。
- P06：渠道目录、账号资产和人工发布任务；首版不接自动发布 API。
- P07：DeepSeek/通义千问 API 采样，以及豆包、腾讯元宝、Kimi、百度 AI 搜索等消费者结果的人工录入。
- P08：模型密钥、模型分工、行业模板、内容规则和监测配置。
