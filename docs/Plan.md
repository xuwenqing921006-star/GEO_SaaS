## 一、范围与交付边界

V1 只交付 Web 网页版，使用现代桌面浏览器访问。项目不建设微信小程序、Windows/macOS 安装包、iOS/Android App、客户门户或其他客户端。

首版由平台负责人单人使用，客户不登录。内容人工发布到系统外的渠道；系统不自动发布、不做审核流、不要求链接或截图回填。

## 三、数据契约摘要

完整数据对象、状态、关系与删除约束见 `PRD.md` 第 7 节；HTTP 请求和响应见 `api-contracts.md`，本文件不重复定义 DTO。

实施硬规则：

- UUID、UTC 时间、枚举英文值和乐观锁 `version` 全栈一致。
- 所有客户业务记录携带 `client_id`，仓储查询必须强制客户隔离。
- 原始文件、提取片段、确认事实、证据、内容版本、监测原文和模型调用分别保存。
- 模型结果不能覆盖确认事实；内容恢复创建新版本。
- API Key 与密码不进入业务响应、日志、文档和测试证据。
- Mock 数据必须是正式契约的有效实例；接口新增字段先改 `api-contracts.md`。

模型真实联调分两级：

1. 没有 Key：只可通过离线 Mock、Schema、降级与错误界面测试，任务标记“Mock 验收”。
2. Key 与额度齐全：Tester 使用莱恩美术脱敏金标集验证两个 Provider、降级链、预算和用量记录，才可标记“真实模型联调通过”。

## 七、开发任务切分原则

开发开始后由 Planner 依据本计划生成 `.sdd/tasks.json`。每个任务必须：

- 只承担一个可独立验证的交付目标。
- 写明拥有的文件、依赖、契约章节、测试命令和用户可见验收。
- 涉及页面业务时同时包含后端真实 API、前端关闭该功能 Mock 和真实联调。
- 由 Developer 实现、Tester 验证；业务阶段由 Product Manager 复核验收证据。
- 发现契约问题先回到 `api-contracts.md` 变更，不在代码中私自增加字段。

## 八、开发顺序

### 阶段 1：Web 前端生产骨架与 Mock

1. 初始化 Web 工程、主题、路由、API Client、Mock 和共享状态组件。
2. 完成 P00—P08，数据严格使用正式 DTO。
3. 执行前端自动检查与独立 Tester 验证。
4. 用户在浏览器验收真实前端页面；这是后端业务开发前的 UI 门禁。

### 阶段 2：基础设施

1. 初始化 Python 工程、配置、日志、FastAPI、PostgreSQL、Alembic、Worker 与 Compose。
2. 完成健康检查、Session、CSRF、密钥加密、文件适配器和任务骨架。
3. Tester 执行安全、迁移、任务恢复和本地 Compose 验证。

### 阶段 3：业务闭环

按依赖推进，每个闭环都要关闭相关 Mock 并由用户从 Web 页面验收：

1. P00/P01：登录、客户与工作台。
2. P02：简版模板、资料上传、知识条目录入和更新。
3. P03/P04：诊断、关键词、问题、计划和简报。
4. P05：模型设置、双模型内容、检查、版本和导出。
5. P06：渠道目录与推荐。
6. P07：DeepSeek/千问 API 监测、人工平台样本、评估与反馈。

### 阶段 4：系统级验证

1. 莱恩美术脱敏金标集完整 E2E。
2. 家政与维修两个合成行业集验证通用模板没有少儿美术硬编码。
3. 安全、备份恢复、模型降级、预算、队列恢复、浏览器兼容和性能测试。
4. 用户执行最终业务验收。

### 阶段 5：可部署包

1. 生成并验证 Docker Compose、Caddy、迁移、备份和回滚说明。
2. 在本地或测试主机执行目标形态冒烟。
3. 不自动购买云资源或生产部署；只有产品负责人明确授权生产发布后才执行。

## 九、测试策略

详细场景见 `delivery/Test-Plan.md`。

| 层级 | 重点 | 最低要求 |
|---|---|---|
| 单元 | 评分规则、事实快照、Schema、自然化保护、渠道匹配、指标计算 | 核心领域分支覆盖率不低于 85% |
| 组件 | 表格、表单、客户切换、任务进度、编辑器、错误状态 | 关键共享组件全部覆盖 |
| API 集成 | 数据库、文件、事务、权限、幂等、版本、任务 | 每个 API 至少成功、验证失败和权限/归属失败 |
| Provider 契约 | Qwen JSON、DeepSeek 检查、超时、限流、错误映射 | Mock 全覆盖；有 Key 时真实冒烟 |
| E2E | P00—P08 主流程和关键异常 | Chromium 必跑，Edge 最新版冒烟 |
| 安全 | Session、CSRF、上传、越权、注入、Secret、日志 | 高危和严重问题为 0 |
| 数据 | 迁移、备份、恢复、版本回滚 | 空库升级与备份恢复均通过 |
| 内容金标 | 事实准确、GEO 结构、自然化、行业通用性 | 阻断事实错误漏检为 0；锁定事实被改写为 0 |

模型内容验收不使用“AI 检测器通过率”作为指标。金标集至少检查：

- 文章没有加入资料之外的企业事实、搜索量、评价、排名或结果承诺。
- 企业名称、地区、服务、客群和限制表达正确。
- 开头直接回应目标问题，存在可独立引用答案段和清晰来源。
- 自然化不改变锁定事实，不虚构第一人称体验。
- 教育模板字段不会出现在家政或维修客户的通用必填区。

| 内容闭环 | 主稿、检查、自然化、版本、导出 | 内容事实准确、自然、可编辑、可回退 |
| 监测闭环 | 多平台样本、指标和反馈 | 正确区分采集方式、失败、提及和推荐 |

## 十一、迁移、备份与回滚

- V1 没有历史生产数据；首次迁移从空库创建 Schema 和种子目录。
- 每个 Schema 变更必须先备份和在副本演练。
- 破坏性变更使用扩展—回填—切换—清理，清理步骤需要独立批准。
- 发布保留上一应用镜像和迁移前备份。
- 回滚顺序：停止新 Worker、切回应用镜像、执行安全 downgrade；不兼容时恢复数据库和文件快照。
- 恢复后校验客户、事实、内容版本、监测样本数量与文件哈希。
- 目标 RPO 24 小时，RTO 8 小时。

## 十二、发布计划

1. 通过全部自动检查、E2E、安全和恢复测试。
2. Tester 出具独立验证证据，Product Manager 复核业务接受标准。
3. 用户完成最终 Web 验收。
4. 生成版本化镜像、Compose 文件、迁移包、备份/回滚说明和环境变量模板。
5. 在目标形态测试环境冒烟。
6. 产品负责人明确授权云资源与生产部署后，才可执行上线。

生产发布检查项以 `delivery/Release-Checklist.md` 为准。开发完成、可部署与已经生产上线是三个不同状态，不得混用。
