# 设计规范

Status: B2 已确认，阶段 C 冻结  
视觉基准：`../prototypes/ai-generated-content-workbench-v1.png`  
交互原型：`../prototypes/index.html`

## 1. 体验方向

这是平台负责人每天使用的专业工作台，不是营销官网。界面应让用户始终看清四件事：当前客户、当前结果级别、事实或风险缺口、下一步动作。

视觉基调为温和、可信、信息密集但不压迫。采用雾白页面、白色工作表面、明亮蓝色主操作与图标、绿色业务结果，以及克制的黄/红风险色。避免大面积深色背景、装饰性插画和没有业务意义的仪表盘数字。

## 2. 信息架构

固定侧边栏：

1. 客户工作台 P01
2. 企业知识库 P02
3. GEO 诊断 P03
4. 关键词与内容计划 P04
5. 内容工作台 P05
6. 渠道建议 P06
7. AI 可见性监测 P07
8. 系统设置 P08

P02—P07 的页面头部必须显示当前客户切换器。切换客户前有未保存内容时，出现“保存并切换 / 放弃并切换 / 取消”三选一确认。

## 4. 页面和组件

共享组件：

- `AppShell`：侧边栏、顶栏、主内容。
- `ClientSwitcher`：当前客户、状态、未保存保护。
- `ResultLevel`：L1—L4 结果阶梯，不显示伪造总排名。
- `NextActionCard`：问题、依据、目标级别、主操作。
- `EvidenceBadge`：已确认、客户提供、外部来源、系统推断、冲突、禁止公开。
- `JobProgress`：任务状态、进度、当前步骤、失败原因、重试。
- `QualityPanel`：八维检查结果和阻断项。
- `SourceDrawer`：事实、来源、更新时间和授权。
- `EmptyState`、`ErrorState`、`Skeleton`：全局状态组件。

页面主要组件与生产映射见 PRD 第 12、14 节。

## 5. 状态设计

| 状态 | 设计要求 |
|---|---|
| 首次空状态 | 解释价值并只给一个主操作，不展示虚假示例结果 |
| 加载 | 2 秒内使用骨架，异步任务显示真实步骤和进度 |
| 成功 | 就地更新并给短暂提示，不用阻塞弹窗 |
| 表单错误 | 字段下方说明；页面顶部给可聚焦问题摘要 |
| 外部服务失败 | 说明失败供应商、是否降级、数据是否保存、如何重试 |
| 事实阻断 | 红色问题清单，跳转对应事实，不允许继续生成 |
| 空监测样本 | 区分“未执行”“平台失败”“已执行但未提及” |
| 权限 | V1 只有登录/未登录，不显示角色管理界面 |

## 6. 表格与编辑

- 事实、关键词、问题和监测样本使用可筛选表格。
- 表头固定；一屏主要操作不超过两个。
- 行内编辑适合短字段；长文本、证据和冲突使用侧边抽屉。
- 危险操作必须二次确认；归档可恢复，不使用永久删除文案。
- 内容工作台使用“文章列表 / 生成后编辑 / 质量与依据”三栏；窄屏时依次落为文章列表、正文、质量与依据。
- 文章只能由 AI 生成任务创建，不提供新建空白正文；生成完成后编辑器才可用。
- 文章列表必须展示标题、类型、主关键词、生成状态、更新时间、质量状态和当前版本。
- 编辑区上方显示企业事实、关键词、用户问题、GEO 优化结构与建议渠道，说明本篇内容是依据什么生成的。
- 模型生成绝不直接替换用户正文，先显示版本差异并允许保留。

## 7. 响应式

- 1440 px 及以上：展开侧边栏，内容区最大宽度 1600 px。
- 1024—1439 px：侧边栏可收起，双栏适度压缩。
- 768—1023 px：只做 Web 页面防溢出处理，侧边栏抽屉化、内容改单列、表格横向滚动。
- 低于 768 px：显示“请使用桌面浏览器访问”的提示，不为手机单独设计业务能力。

不得因窄屏隐藏事实来源、风险或保存状态。

## 8. 可访问性

- 正文与背景对比度至少 4.5:1，大字号至少 3:1。
- 所有操作可键盘到达；焦点顺序与视觉顺序一致。
- 图标按钮有中文可访问名称，状态不只依赖颜色。
- 表单错误与字段关联，异步任务状态使用非打扰式实时区域。
- 动画遵循系统“减少动态效果”；骨架不快速闪烁。

## 9. 设计非目标

- 不做客户登录门户、团队角色、审核队列和自动发布状态。
- 不做微信小程序、桌面安装包、原生移动 App 或其他独立客户端。
- 不把 AI 平台展示成传统搜索排名榜。
- 不用“保证收录”“保证推荐”“AI 检测通过”等结果承诺。
- 不为了通用行业把所有行业字段堆在同一张表；通过行业模板动态显示。
- 原型 HTML 不直接复制为生产代码，生产实现必须遵守阶段 C 架构。

## 10. T-016 明亮视觉与弹窗规范

- 应用侧栏、顶栏、内容区与表单面板均使用白色或雾白色，不使用大面积深绿色背景。
- Logo 使用蓝色定位图形；八个主导航项使用语义化 SVG 图标，不使用单字占位图标。
- 主按钮、当前导航、筛选选中态和可操作链接使用蓝色；成功状态与业务指标继续使用绿色。
- 弹窗分为 500 px、720 px、1040 px 三档；标题区、正文区和操作区层级固定，长正文独立滚动。
- 弹窗支持 Escape 关闭、打开时锁定页面滚动、关闭后恢复原焦点；图标关闭按钮必须有中文可访问名称。
- 1024、1280、1440 三种桌面宽度不得出现页面级横向溢出，内容工作台在中等宽度自动调整列布局。
