# T-072 一点号多账号与专用自动发布闭环

## 目标

在现有发布渠道体系中接入一点号，支持运营人员以独立的本机浏览器会话登录、检测、生成适配文章、提交发布并回查审核结果。

## 范围

- 一点号账号配置、独立会话、登录检测、启用与暂停；系统最多保存 5 个连接账号，但界面提示平台对同一企业主体的账号认证限制。
- 一点号专属的文章生成合同、确定性质量门禁和图片预处理。
- 发布页字段适配、AI 内容声明、提交回执和内容管理状态回查。
- 内容工作台、文章发布与渠道配置页面的一点号显示与选择。

## 非范围

- 不保存第三方账号密码，不绕过验证码、安全验证、风控或审核。
- 不承诺一点号提供公开发文 API；本任务不构建外部 API 对接。
- 未在真实已登录账号上验证的页面字段，不进入真实自动提交路径。

## 用户旅程

1. 运营人员在渠道配置创建一点号账号并在独立浏览器窗口完成登录。
2. 系统检测到有效会话后，允许选择一点号生成适配文章。
3. 文章生成阶段按一点号规则主动规避广告、导流、标题党、低质和同质化风险。
4. 运营人员在文章发布页提交文章；系统准确区分审核中、已发布、驳回、登录失效和安全验证。
5. 审核完成后，系统从内容管理中保存公开原文链接。

## 验收标准

- 一点号与现有平台一样支持独立浏览器会话、每日检测和发布前复检。
- 每篇一点号文章在保存前通过一点号专属质量门禁；不含联系方式、二维码、站外导流、强营销或标题党表达。
- 未得到确认的真实页面字段只允许本地模拟测试或可见填充验证，不自动点击最终提交。
- 提交成功但仍在审核时记录为“审核中”，不误报发布失败。
- 平台图片、标题和正文约束保留来源与核验日期；待真实编辑器验证的规格明确标识为系统保守默认值。
