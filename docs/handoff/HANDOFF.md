## 1. 接手方式

推荐先按 README 配置独立的新环境，初始化自己的负责人账号，验证登录与只读页面，再按未完成任务清单确定工作优先级。开发者可以使用自己的 IDE、AI 助手、测试与协作方式。

无需安装 ECC_V2、调用其 Router/guard/doctor、读取原作者电脑路径或更新 `.sdd` 才能开发。`AGENTS.md` 提供通用项目规则，`CLAUDE.md` 与 Cursor 规则只是可选工具入口；没有使用它们也能正常运行工程。

历史 `.sdd/` 原始需求、任务、决策和报告保留供核对。本轮新增 T-073 是交接整理的过渡记录，不是业务功能任务。未来可以迁移到 GitHub Issues、项目看板或团队自己的文档体系；本轮没有代替团队选择或迁移历史状态。

## 2. 产品与当前完成度

这是单负责人、多客户的 Web 工具，没有客户自助注册、客户登录或组织多角色权限。主要路径为：客户 → 知识库 → GEO 诊断 → 关键词 → 内容生成任务 → 确认文章 → 文章发布与审核回查 → AI 可见性监测。

交接前原始业务任务共 65 项：26 项标记 `passed`，38 项 `in_progress`，1 项 `failed`。这些是历史记录，不等于本轮对全部功能重新验收。原业务续做任务为 T-072「一点号多账号与分阶段自动发布闭环」；本轮为了整理交接新增 T-073，不改变 T-072 的实现与待验收状态。

详细清单逐项列出标题、原状态、依赖、验收条件与报告，见 [OPEN-TASKS.md](OPEN-TASKS.md)。未完成任务可能已经有部分或完整开发实现，接手者应检查现有代码与报告，再判断是补实现、回归验证还是等待业务确认。

### 建议优先核验

1. T-063 全流程验收是历史失败结论。后续 T-068 等报告声明修复了部分工程和业务问题，但任务仍未完成独立复验；不能沿用旧失败数量断言当前仍失败，也不能据开发报告标成全绿。
2. T-064—T-068 是关键词、内容任务、生成质量与确认发布队列的连续变更，先核验完整流程与接口兼容。
3. T-069—T-072 涉及渠道专用适配。真实平台页面、账号、提交和审核结果需要分平台核验，固定模拟通过不代表真实发布可用。
4. T-014、T-016、T-017 以及其他旧 `in_progress` 记录需要对照后续迭代确认是否已被替代或仍缺验收，不批量改状态。

一点号当前代码在真实浏览器适配器中停止最终提交，提示先完成真实编辑器字段验证；这项保护保留。它已经出现在目录与部分生成规则中，不代表真实自动提交已开放。企鹅号、网易号和其他平台的真实账号验证边界以最新任务和对应报告为准。

## 4. 配置与运行环境

| 文件 / 设置 | 作用 |
| --- | --- |
| 根 `.env.example` → `.env` | Docker Compose 的本机参数；开发示例不用于正式部署 |
| `backend/.env.example` → `backend/.env` | 从后端目录运行 Python 的数据库、存储、主密钥和执行模式 |
| `frontend/.env.example` → `frontend/.env.local` | Vite 的真实 API / Mock 切换 |
| 启动终端的 `VITE_API_PROXY_TARGET` | 非默认 API 端口的代理目标；当前配置仅从进程环境读取，不读取 `.env.local` 的该项 |
| `.env.production.example` | 生产参数占位示例，真实配置保存在安全位置 |
| `GEO_APP_MASTER_KEY` / `APP_MASTER_KEY` | 分别为 Compose 与 Python 侧的同一加密主密钥 |
| `MODEL_EXECUTION_MODE` | `live` 调用已配置模型；`fixed_mock` 仅用于明确的测试/模拟 |
| `PUBLISHING_EXECUTION_MODE` | Python 支持 `live_browser` / `fixed_mock`；基础 Compose 未映射这项环境变量，不应假定在根 `.env` 添加它就会改变容器 |
| `BROWSER_EXECUTABLE_PATH` | 原生模式可指定本机 Chrome/Edge；基础镜像不提供桌面浏览器 |

API 和 Worker 必须连接同一业务库、同一文件存储并使用同一主密钥。运行角色与迁移角色独立，不能用数据库管理员身份掩盖运行权限问题。真实模型调用可能产生费用，普通交接验证不自动授权调用或公开发布。

原作者当前本机使用旧容器 `geo-saas-t008-pg`、55432 端口和 `geo_saas_t008` 库；它们是本机历史环境，不属于同事需要复刻的标准配置，也不会随 Git 仓库提供。新的开发覆盖层默认也使用 55432，若与本机环境冲突，应设置自己的 `DEV_DB_PORT` 和后端 `DB_PORT`，不要停止无关服务。

旧 `backend/scripts/start-local-*.ps1` 绑定这套历史环境，保留用于追溯。本次提供的 README 使用明确的新环境命令，不要求执行旧脚本。

## 5. 数据、文件、账号与密钥如何交接

代码交接默认不包含运行数据。新负责人、客户数据、模型配置和发布账号需要在独立环境初始化；如果团队确实需要现有业务数据，另做明确的数据交接：

| 内容 | 交接方式 |
| --- | --- |
| 源码、迁移、测试、环境示例、产品文档 | 候选 Git 文件；首次提交前逐项审查 |
| 数据库、客户资料、企业图片、内容文件 | 单独受控备份与传输；数据库与文件存储需要一致性核验 |
| 原环境的加密模型配置 | 恢复旧数据时需要对应原主密钥，通过安全渠道交接；或按团队方案重新配置凭据 |
| 负责人密码 | 新环境自己初始化；现有账号通过正式改密或团队约定处理，不在文档保存明文 |
| 第三方模型密钥 | 团队自己的凭据管理方式，不提交到 Git |
| 自媒体密码、验证码、Cookie、浏览器 profile | 不交付到代码仓库；同事在自己电脑完成授权登录与人工安全验证 |
| 日志、覆盖率、临时截图、数据库 dump | 本机生成物，Git 默认忽略；必要证据另行脱敏分享 |

本轮没有导出、恢复、搬迁或删除任何真实数据，没有重置负责人密码或渠道账号，也没有修改正在使用的密钥。

本轮验证交接文档与配置的正确性，并比对 251 个业务工程文件及原始 65 项任务。没有重新跑全量业务回归、付费模型、真实渠道发布或完整空库容器启动；不会将“配置可解析”写成“所有业务通过”。

## 7. Git 状态与后续上传

交接整理阶段初始化了独立本地 `main` 仓库，当时没有提交、远程或 GitHub 推送；上层开发工具仓库不包含本项目业务历史。后续上传将保留目标仓库已有的初始化提交，再提交项目交接基线，不虚构历史开发提交。当前仓库地址与协作方式见仓库说明。

`.gitignore` 排除真实环境、数据库备份、存储、浏览器会话、日志、生成结果与本轮本地备份，保留源码、两类环境示例和历史任务资料。`.gitattributes` 为 shell 脚本等文本指定换行规则，帮助新检出环境保持可执行脚本的 LF 换行。

上传前审查候选文件、运行敏感信息检查，再提交交接基线并推送。私有仓库也不存真实密钥、客户原始文件或第三方登录会话；当前忽略规则不等于所有历史文档都已脱敏。

本轮修改前入口与配置副本位于本机 `.sdd/temp/T-073-before/`（被 Git 忽略），可用于撤回本次整理。不要将整个工作目录打包上传，因为被 Git 忽略的真实数据仍保留在本机。
