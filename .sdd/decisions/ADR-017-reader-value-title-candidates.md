# ADR-017：把候选标题保存到文章版本

## 状态

已采用，2026-08-04。

## 背景

只调整提示词但仍只保存一个标题，会让运营人员无法比较专业知识、场景、本地决策等
不同角度，也无法追溯某个版本当时有哪些可选标题。把候选标题放在文档主表又会让历史
版本之间互相覆盖。

## 决策

- 在 `content_versions` 增加可空 JSON 字段 `title_candidates`。
- 每项只保存 `title` 与 `title_type`，不保存模型推理过程。
- API 为加法兼容：旧版本返回空数组；新版本返回候选数组。
- 当前采用的标题仍使用原有 `title` 字段，避免影响发布、封面、导出和现有客户端。
- 手工编辑或渠道适配创建新版本时继承候选，并把新的当前标题置于首项。

## 数据与兼容性

- 迁移：0025 增加可空 JSON 列，不改写旧正文和标题。
- 回滚：先回滚应用，再执行 0025 downgrade 删除该列；只丢失候选标题，不影响正式标题
  与正文。
- API：现有字段不变，前端把候选字段声明为可选以兼容旧响应和 Mock 数据。

## 安全与隐私

- 候选标题执行与正式标题相同的联系方式清理。
- 不保存模型思维链或内部来源标识。
- 候选标题仍受客户数据边界和文章版本访问控制保护。

## 取舍

- JSON 比独立标题表更适合每版本最多 5 条的小规模有序数据，减少无必要的关联和接口。
- 旧版本不自动生成看似由 AI 提供的替代标题，避免混淆历史事实。
