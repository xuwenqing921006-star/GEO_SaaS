# ADR-021：一点号采用分阶段浏览器会话发布

## 状态

Accepted，2026-08-10。

## 决策

- 一点号复用 ADR-016 的独立本机浏览器 profile、每日复检和发布前复检机制；不保存密码，也不规避平台验证。
- 目前未发现面向普通创作者的公开发文 API，首版按浏览器辅助发布设计，不表述为官方 API 接入。
- 一点号文章默认采用知识科普、经验方法、案例观察或故事化叙述；不生成手机号、微信、二维码、网址、报名咨询、优惠、强推荐或商业业务介绍。
- 生成阶段要求标题与正文一致、正文具备至少三个有效内容部分，并把 AI 内容声明作为发布字段而非正文营销信息。
- 平台公开规则要求图文相关、排版清晰，并将图片型文章少于三图视为低质量风险。系统为一点号准备三张相关正文图片；封面比例、编辑器字段与最终提交按钮在真实已登录账号完成只填充验证后才解除真实提交通道。
- 每个企业主体在一点号官方规则下最多认证两个企业账号；系统可保存最多五个账号连接记录，但不试图绕过平台主体认证限制。

## 原因

一点号明确禁止广告、营销、低质量和同质化内容，并实行机器与人工审核。先固化生成规则、会话与审核回查，再依据真实发布页验证自动化选择器，可以降低误发、误判审核中和账号处罚风险。

## 安全、兼容与回滚

- 不新增账号密码、验证码或个人身份信息字段。
- 现有 `publishing_accounts` 与 `content_publications` 的字符串渠道字段可直接兼容，无数据库迁移。
- 回滚时移除一点号目录、提示词和适配器即可；已有其他渠道账号和发布记录不受影响。
