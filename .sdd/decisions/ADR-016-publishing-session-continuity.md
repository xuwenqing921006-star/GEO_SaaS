# ADR-016：发布账号使用独立持久会话与主动复检

## 状态

Accepted，2026-08-04。

## 决策

- 头条号、百家号、网易号、搜狐号、企鹅号的每个账号继续使用独立的本机浏览器 profile。
- 不保存第三方平台账号密码，不尝试绕过扫码、验证码、安全验证或平台风控。
- Worker 每 5 分钟扫描一小批到期账号；每个已连接账号距离上次有效检测满 24 小时后自动复检一次。
- 每次发布前必须再次复检目标账号。复检未通过时停止该目标任务，不打开发布编辑器，也不影响其他账号。
- 登录失效或需要安全验证时暂停对应账号；浏览器登录窗口仍在占用 profile 时只延后检测，不误判为登录失效。
- 渠道配置页根据上次检测时间展示“即将自动复检”“需要自动复检”“登录已失效”等状态，并每分钟刷新一次。
- “重新登录”始终打开该账号原有 profile，运营人员完成扫码或安全验证后即可沿用原配置。

## 原因

第三方内容平台通常不会提供稳定、可预知的 Cookie 失效时间，并且可能因平台策略提前使
会话失效。因此不能承诺“永久登录”，也不能用数据库中的历史连接状态直接判断发布可用。
24 小时巡检负责提前暴露常见失效，发布前复检负责守住最终发布入口。

## 安全与隐私

- 系统不新增账号密码、短信验证码或扫码信息的持久化字段。
- 本机 profile 目录按平台和账号 ID 隔离，账号之间不共享 Cookie。
- 自动检测只访问平台官方创作后台；检测遇到验证即停止，不执行规避操作。

## 迁移与回滚

本决策复用 `publishing_accounts.last_checked_at`、`connection_status` 和现有 profile 目录，
无需数据库迁移。回滚时可移除 Worker 巡检与发布前复检逻辑；已有浏览器 profile 和账号
记录保持不变。
