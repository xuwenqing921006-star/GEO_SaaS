# T-032 经验记录

- AI 重新生成不能把完整旧稿继续交给模型，否则“重新生成”容易退化为局部修补。
- 知识库原文可以保留，但进入写作模型前必须转成安全事实层：拆分长句、移除高风险
  宣传分句、处理过时动态数字，并收敛互相冲突的属性口径。
- 生成模型与审核模型必须共享同一事实边界；否则生成端做出的保守处理会被审核端
  再次误判。
- 审核提示中的内部 ID 即使不属于正文，也可能被模型误报，因此审核上下文应从数据
  结构上彻底排除内部标识。
- 中文数量检查需要区分“设有一家门店”的规模主张与“推荐一家、选择一家”的普通
  指代表达。
- 关键词收录友好不等于机械精确匹配。首段自然完整出现一次即可，检查规则应允许
  “在某地寻找某服务”这类少量连接词。
- 真实模型验证应选一篇代表文章形成“旧版问题 → 重写 → 独立复核”的闭环，避免只
  依赖模拟返回判断内容质量。
- 人工修改建议是文章版本的一部分，不能只存在于一次任务请求中；否则之后重新质检
  会失去原判断标准。
- 模型审校可能把“符合要求、无需修改”也错误放进问题数组，结构化校验后仍需过滤
  结论明确为无问题的记录。
- 千问适合常规批量写作；需要逐条遵守复杂人工约束的重写采用 DeepSeek 主写更稳定。
- 一次写作加一次审核仍可能产生新问题。自动修复应有明确上限，本项目采用最多两轮，
  提前通过即停止，超出上限继续阻断而不是无限消耗。
