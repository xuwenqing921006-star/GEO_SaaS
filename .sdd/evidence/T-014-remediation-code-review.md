## 关键实现复核

### 1. 具名渠道成品的选择、编辑和映射更新

- `frontend/src/views/ContentWorkbench.vue:150-166` 将 `channel_variants` 与各自版本、质量检查和渠道名称组成独立卡片。
- `frontend/src/views/ContentWorkbench.vue:319-335` 的 `selectChannelVersion` 会在无未保存修改冲突时载入所选版本，并滚动到编辑器。
- `frontend/src/views/ContentWorkbench.vue:940-1015` 每张渠道卡片提供“编辑此版本”，并保留该版本自己的预览和导出入口。
- 编辑器同时支持标题和正文修改；保存渠道成品时，`frontend/src/views/ContentWorkbench.vue:357-395` 发送：
  - 当前文档 `version`
  - 编辑后的 `title`、`body_markdown`
  - `source_version_id`
  - `channel_id`
- 后端 `UpdateDocumentInput` 要求 `source_version_id` 与 `channel_id` 成对出现（`backend/app/content.py:121-133`），普通主稿保存仍可省略，保持原 API 兼容。
- PATCH 在同一事务内：
  - 使用 `FOR UPDATE` 锁定文档，并校验文档乐观版本；
  - 验证 source version 属于当前文档；
  - 锁定当前 document、channel、source version 对应的精确渠道映射；
  - 映射已过期时返回冲突，不会覆盖其他写入；
  - 创建新的 `channel_variant` 版本、执行独立质量检查并更新渠道映射。
- 锁顺序与渠道 Worker 的文档优先流程一致，未发现新增死锁次序。
- API 合同已同步记录可选字段及其成对语义（`docs/api-contracts.md:987`）。

### 2. 真实问题式头条标题

- `_channel_variant_title` 会按首个中英文冒号或竖线切分标题，去掉尾部标点，再识别“怎么、如何、哪些、是否、推荐”等问题语义。
- 对 `即墨区少儿美术培训怎么选: 公开信息核验指南`，头条成品为：
  - `即墨区少儿美术培训怎么选？先看这些已确认信息`
- 后端专项测试明确断言：
  - 标题以真实问题开头；
  - 不包含“核验指南怎么”；
  - 不包含已禁用的时效承诺式表述。

### 3. 重复渠道生成的稳定基线

- 前端 `channelGenerationSource` 默认选取最近的 `change_type !== "channel_variant"` 版本。
- 后端不信任调用方：若收到的 source 本身是 `channel_variant`，会再次查询同一文档最近的非渠道版本作为生成基线。
- 回归测试故意以已编辑渠道版再次生成头条版，最终标题中的“先看这些已确认信息”只出现一次，证明没有后缀和结构累加。

### 4. P1 样本和指标分母

T012 的真实 Chromium 流程已明确验证：

- 夸克 P1：提交成功回答；
