# T-053 读者价值标题与候选标题工作流

## 变更目标

把文章标题从“地区 + 关键词 + 固定结论”的批量稿写法改成读者价值优先。文章生成时由
AI 同时产出多个实质不同的标题方向，运营人员在编辑页直接选择或继续修改。

## 用户与业务价值

- 用户：平台唯一运营人员。
- 业务目标：降低资讯平台对批量低质内容的识别风险，同时保持企业、地区、服务之间的
  自然语义关联，便于后续检索、引用和品牌核验。
- 非承诺：标题和正文质量门禁只能降低风险，不保证平台审核、推荐或大模型收录。

## 范围

1. 写作模型输出 `title`、3 个不同方向的 `title_candidates` 和正文。
2. 候选方向覆盖专业知识、一般场景、本地决策、自然问答和品牌核验，按文章内容选择
   其中最适合的 3 类。
3. 关键词仅作为选题依据，不强制完整写入标题；地区、业务、品牌、年龄和服务清单不得
   同时堆入标题。
4. 没有真实案例事实时不得写成真实学员、家长或客户故事。
5. 渠道适配采用模型生成的渠道标题，不再用固定后缀覆盖模型标题。
6. 内容工作台编辑弹窗展示候选标题卡片；点击只更新标题输入框，保存后才形成新版本。
7. 质量门禁新增标题过载、低质模板和标题正文严重不匹配检查。

## 非范围

- 不重写已有文章，不回填旧文章的虚构候选标题。
- 不自动发布或重新发布任何文章。
- 不更改关键词策略、企业知识库或渠道账号。
- 不把“故事性”理解为允许虚构真实客户案例。

## 页面与交互设计

### 页面清单

- 内容工作台 → 文章详情 → 编辑文章弹窗。

### 流程

```text
AI 生成文章
  -> 保存当前标题 + 候选标题
  -> 运营打开编辑弹窗
  -> 选择候选标题或手工输入
  -> 保存
  -> 新版本继续执行事实与质量检查
```

### 状态

- 加载：沿用文章详情加载状态。
- 成功：展示 1—5 个候选标题，当前标题卡片高亮并使用 `aria-pressed`。
- 旧数据：候选列表为空时不展示卡片，旧正文和编辑能力保持不变。
- 保存失败：沿用编辑弹窗错误提示，不修改当前版本。
- 响应式：桌面三列；窄屏降为单列，避免标题文字被截断。
- 权限：沿用当前单用户登录边界。

### 原型豁免

本次是既有编辑弹窗内的局部增量，不改变导航、页面结构或核心任务流；用户已确认标题
方向并要求开始修改，因此记录原型豁免，以真实 Web 页面和自动化检查作为设计证据。

## 验收标准

1. 新生成或 AI 重新生成的版本 API 返回至少 3 个去重候选标题，当前标题位于首项。
2. 真实模型提示要求候选标题在角度上实质不同，并禁止虚构案例。
3. 渠道真实模型返回的标题被保留，不再强制拼接“先看结论”等固定后缀。
4. 运营可在编辑弹窗点击候选标题，并继续手工修改后保存。
5. 标题候选随版本持久化；手工标题会成为新版本的当前候选。
6. 资讯平台标题过长、明显批量模板或与正文严重不匹配时阻断发布。
7. 旧版本仍可查看、编辑和发布检查，不因新字段报错。

## 产品确认

2026-08-04，用户确认文章应以专业性或故事/场景性内容为主、营销只占少量，并确认标题
需要同步修改，随后明确“开始修改”。
