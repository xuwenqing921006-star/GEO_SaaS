# T-055 基于来源证据的竞品 GEO 诊断

## 变更目标

在现有 DeepSeek、通义千问、豆包 GEO 自动诊断基础上增加文心一言，并把诊断从“是否提及
客户品牌”扩展为“客户与竞品如何出现、回答参考了哪些公开来源、哪些发布渠道在当前样本中
反复成为来源、据此应做什么”。

## 用户与业务价值

- 用户：平台唯一运营人员。
- 业务目标：用可追溯的回答和来源证据解释竞品为何更容易被提及或推荐，并把诊断结果直接
  转为内容和渠道动作。
- 非承诺：API 样本不等同于消费者 App 的每次回答；来源出现频率不等同于平台官方算法
  权重；系统不承诺排名、推荐或收录结果。

## 范围

1. GEO 诊断固定展示 DeepSeek、通义千问、豆包、文心一言四个平台。
2. 系统设置增加文心一言（百度千帆）API 的密钥、模型、预算、超时和连接测试。
3. 千问使用百炼联网搜索并读取 `search_info.search_results`。
4. 豆包使用火山方舟 Responses API 的 Web Search，并读取回答引用及 URL。
5. 文心一言使用百度千帆联网搜索并读取 `search_results`。
6. DeepSeek 继续执行回答检测；官方 API 未返回网页来源时明确标记“当前接口不提供来源证据”，
   不伪造引用。
7. 每个平台保存回答摘要、可见来源、其他品牌/机构提及、提及顺序和观察依据。
8. 按来源域名归并百家号、搜狐号、头条号、网易号、知乎、微信公众号等渠道，作为解释
   竞品为何更突出的辅助证据；不继续扩展为通用的“平台渠道权重”产品。
9. GEO 优化建议增加竞品差距和渠道动作；每条建议必须说明观察依据，来源建议应能打开原文。
10. 保存平台回答中包含竞品的原句，以及搜索接口返回的来源摘要；据此识别跨平台重复出现、
    推荐命中、回答位置领先、多来源支持、服务信息、信任信息和决策信息等可见优势。

## 诊断与评分规则

- 现有 100 分可见性评分保持：品牌出现 30%、地区与主营关联 25%、推荐命中 25%、可核验
  企业事实 15%、可见来源 5%。
- 未配置、请求失败或不支持来源的情况不伪造来源；平台请求失败不计入综合评分。
- 竞品“更高”只依据同一次回答内的出现顺序、推荐语、跨问题重复出现和来源标题直接提及；
  不推断平台未公开的内部排序分。
- 渠道信号仅作为竞品证据的辅助观察，不作为通用渠道权重结论；用户要求的跨平台渠道优先级
  以独立调研清单交付，不继续开发成产品矩阵。

## 页面与交互设计

- 系统设置：增加文心一言配置卡片。
- GEO 诊断：
  - 平台表增加来源状态与来源数量；
  - 回答摘要中展示对应来源；
  - 增加“竞品出现原因”模块，展示优势信号、平台回答原句、参考资料和对应优化动作；
  - 增加“来源影响信号”模块，可打开证据链接；
  - 优化建议优先展示有回答或来源证据支撑的动作。
- 无来源时显示能力限制说明，不使用空白或 0 分冒充真实观察。

## 非范围

- 不自动登录或操控四个平台的消费者 App。
- 不抓取登录后隐藏内容，不绕过验证码或平台风控。
- 不把本次来源分布固化为永久平台权重。
- 不改变 AI 可见性监测页面仍采用的三平台范围。
- 不自动发布新文章。

## 验收标准

1. 文心一言出现在 GEO 诊断和系统设置，但不进入 AI 可见性监测目录。
2. 未配置文心密钥时显示未配置且不参与综合评分。
3. 千问、豆包、文心真实返回来源时保存标题、URL、站点和对应问题；DeepSeek 无来源能力时
   明确说明。
4. 竞品卡片只展示从回答或来源标题中提取到的其他机构，且给出提及次数、顺序或来源依据。
5. 渠道信号表展示观察次数、覆盖平台、覆盖问题、信号分和置信度，并说明不是官方权重。
6. GEO 建议能引用竞品或渠道证据；没有证据时不生成确定性竞品结论。
7. 既有诊断 JSON 仍能正常读取，旧结果没有新字段时页面不报错。
8. 新诊断保存来源摘要和竞品回答原句，竞品建议必须能对应到可见信号，不能只输出通用建议。

## 产品确认

2026-08-04，用户明确要求 GEO 诊断增加文心一言，并基于千问、DeepSeek、文心一言、豆包
的关联文章或参考资料反推竞品收录原因并生成优化建议。用户随后澄清：跨平台渠道优先级只需
调研罗列，不需要继续开发为独立产品功能。
