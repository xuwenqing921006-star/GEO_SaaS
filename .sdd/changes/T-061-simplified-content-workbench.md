# T-061 简化内容工作台与生成阶段质量闭环

## 目标

把内容工作台收敛为“选择关键词和平台 → AI 生成 → 查看或修改 → 选择账号发布 → 查看结果”五步流程。平台规则、联系方式清理和可自动修复的内容质量问题由系统在生成阶段处理，不把内部版本、提示词快照或常规复检操作暴露给单人运营用户。

## 范围

- 简化文章生成区、统计卡、文章列表、编辑弹窗和发布弹窗的文案与操作。
- 文章列表只呈现标题、关键词、发布平台、内容状态、发布状态、更新时间和必要操作。
- 风险文章不能进入发布；发布账号默认不勾选，避免误发。
- 初次 AI 生成后自动检查事实、营销表达、题文一致、关键词堆砌、渠道联系方式和资讯平台低质风险；可修复问题在后台最多重写两次。
- 人工编辑和 AI 重写后继续自动执行质量检查。

## 不在本次范围

- 不迁移或删除历史文章、版本和发布记录。
- 不修改各发布平台的浏览器自动化流程。
- 不新增平台账号、模型供应商或客户报告。
- 不保证平台审核、收录、引用或推荐结果。

## 验收标准

1. 页面主线只保留生成、文章列表、编辑和发布，不再把提示词快照、批量复检和内部渠道版本作为主要操作展示。
2. 文章内容状态明确区分生成中、可发布、需调整和生成失败；需调整文章不能点击发布。
3. 生成时已应用目标平台规则，联系方式和可自动修复的质量问题不会留到发布前才处理。
4. 发布窗口默认不选择任何账号，用户明确选择后才创建真实发布任务。
5. 自动修复后仍无法通过的事实或合规问题，才在编辑页展示具体原因和修改建议。
6. 前端单元、类型、Lint、构建及后端内容定向测试通过。

## 兼容、回滚与安全

- API 请求结构保持兼容，旧通用稿和旧渠道稿仍可查看、编辑与发布。
- 回滚前端即可恢复旧展示；后台自动修复只产生正常文章版本，不修改知识库事实。
- 发布仍由用户明确点击并选择账号触发；本次不会自动真实发布。
