# T-029 内容工作台修正闭环与渠道发布合规

## 目标

让运营人员看得懂文章为什么“待修正”、可以在哪里处理，并能用一句修改建议让 AI
重新生成完整版本；同时让关键词选择、文章筛选和人工发布记录形成顺畅闭环。

## 当前问题

1. 内容生成按钮同时要求关键词策略属于最新诊断。运营人员重新勾选旧策略中的关键词后，
   虽然该关键词仍真实有效，前端仍把按钮禁用。
2. “待修正”来自质量检查，但文章详情没有展示具体问题、建议和直接修正入口。
3. “标记已发布”把内部质量门禁和外部发布事实混在一起。文章即使已经由运营人员发布，
   系统仍不能记录。
4. 文章列表只有当前/已删除切换，无法按关键词、类型、发布状态或适合渠道查找。
5. 编辑只支持手工改标题和正文，不能输入修改目标后让 AI 重新生成。
6. 通用稿可以直接复制到搜狐号等平台，未充分提示“通用稿不等于渠道合规稿”。

## 推荐流程

```text
选择关键词
  -> 配置内容形式与目标渠道
  -> AI 生成
  -> 查看质量问题
  -> 手工编辑，或输入修改建议让 AI 重新生成
  -> 选择渠道专用版本
  -> 人工发布
  -> 标记已发布
```

## 页面变更

- 生成按钮仅在无关键词、知识/诊断过期、模板未加载或任务执行中禁用。
- 旧诊断生成的关键词保留提醒，但运营人员明确选择后可继续生成。
- 列表增加关键词、类型、发布状态、适合渠道筛选和结果计数。
- 待修正状态展示阻断数量；编辑弹窗展示每项问题和建议。
- 编辑弹窗增加“修改建议”“重新生成渠道”和“AI 重新生成”。
- 标记已发布用于记录人工操作；质量问题继续保留并显示，不假装内容已经通过检查。
- 已发布记录独立于文章当前状态保存；发布后再次编辑或重新生成，列表仍可按“已发布”
  找到，并额外提示当前版本是否已经发布。
- 通用稿明确提示发布前应生成或重新生成目标渠道版本。
- 前端会拉取全部文章分页数据后执行组合筛选，避免只筛选前 100 篇。

## 后端变更

- 增加 `regenerate` 内容操作，输入源版本、修改建议和可选目标渠道。
- 重新生成继续使用冻结事实、提示词版本、渠道联系方式策略与独立质量检查。
- 发布事实写入独立记录，不再要求内容先通过内部质量门禁，但不得用于尚未生成、生成失败
  或已删除内容；后续质量状态不会覆盖历史发布事实。
- 批量生成接口在后端校验最新诊断快照，避免绕过页面直接使用已过期企业资料。
- `omit` 渠道规则同时清理电话、微信、QQ/群、公众号、邮箱、二维码、外链和私信导流。
- 版本新增 `regenerated` 类型，保留历史版本。

## 非范围

- 不自动登录或向第三方平台发布。
- 不承诺通过任何平台审核。
- 不自动修改或删除历史文章。
- 不把平台规则当作永久不变；页面仍提示发布前复核最新规则。

## 验收标准

以任务 T-029 的 acceptance criteria 为准。
