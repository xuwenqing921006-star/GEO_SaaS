# T-046 豆包监测收口与四平台多账号发布

## 本轮目标

- GEO 诊断和监测只使用 DeepSeek、通义千问、豆包。
- 豆包通过火山方舟官方 OpenAI 兼容接口调用；没有密钥或模型配置时只显示未配置。
- 自动发布覆盖头条号、百家号、网易号、搜狐号。
- 每个平台最多五个账号；每个账号拥有独立浏览器 profile、连接状态和启停开关。
- 内容工作台发布时多选平台账号，每个目标生成独立发布记录与 Worker 任务。
- 客户结果报告不在本轮开发。

## 发布状态机

账号：`disconnected -> awaiting_login -> connected -> enabled`。登录失效、验证码或身份验证
分别进入 `needs_login`、`needs_verification`，并只暂停对应账号。

任务：`queued -> publishing -> published`，失败按原因进入 `failed`、`needs_login`、
`needs_verification` 或 `rejected`。只有平台成功提示、内容管理记录或公开文章地址至少一个
成立时，任务才能标记为 `published`。

## 内容与账号匹配

发布请求传入账号 ID 列表。服务端按账号的平台找到相同 `channel_id` 的文章渠道版本；缺少
渠道版本时整次请求返回明确错误，不允许用头条号版本直接发布到其他平台。

## 安全与边界

- 不保存第三方平台密码，只保存本机浏览器登录状态。
- 不绕过验证码、风控或身份验证。
- 不把“点击了发布按钮”当成发布成功。
- 同一账号的发布任务串行执行，避免浏览器 profile 被并发占用。
- 百家号、网易号、搜狐号普通内容账号没有在本项目中确认到可直接使用的通用公开发文 API，
  本轮采用隔离浏览器适配器；平台页面变化会返回“适配器需更新”，不会静默成功。

## 会话续期与主动检测

- 每个账号沿用独立持久浏览器 profile，不保存平台账号密码。
- 已连接账号距离上次检测满 24 小时后由 Worker 自动复检；扫描器每 5 分钟处理最多 5 个
  到期账号，20 个满配账号可在一个扫描周期组内完成。
- 每次发布前强制复检。登录失效、需要验证或连接异常时，该账号的发布任务立即停止。
- 登录窗口正在占用 profile 时延后后台复检，避免把“窗口未关闭”误报成会话失效。
- 渠道配置页显示账号健康状态、最近检测、下次自动检测和醒目异常提示；“重新登录”复用
  原 profile，扫码或验证一次即可续期。
- 平台真实 Cookie 过期时间不可可靠预知，页面中的“即将”只表示即将到 24 小时复检时间，
  不伪造平台过期时间。

## 验证边界

Developer 只记录实现和开发侧验证。任务保持 `in_progress`；真实账号发布、独立 Tester 和
产品验收完成前，不标记为通过。
