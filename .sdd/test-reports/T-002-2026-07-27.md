## 接受标准证据

1. P00 负责人登录与 P01 客户工作台符合首版 Web 范围。
   - 实现负责人登录、客户搜索、筛选、排序、分页、创建、编辑、切换、暂停、恢复、归档与恢复。
   - 工作台显示客户资料完整度、当前 L 级、阻断项、下一步条件和行动。
   - 后续 P02—P08 模块明确显示为“后续模块”，没有伪装为已完成能力。
   - 页面只提供 Web 客户端；767px 及以下显示“请使用桌面浏览器访问”。

2. Session、路由、查询参数和未保存保护通过独立浏览器验收。
   - 开发 Mock 登录后整页刷新仍恢复工作台；仅保存开发态布尔登录标记，不保存用户名、密码、Session、CSRF 或客户数据。
   - 401 会清理 Session、CSRF、当前客户与 Query Cache，并返回登录页。
   - `q/status/sort/page/page_size/clientId` 可写入 URL，并可随浏览器历史恢复。
   - 客户切换、同路由查询变更、离页和退出均受统一 dirty 保护。
   - 保存、放弃、取消三条路径均可恢复，取消和 Escape 会清理待执行导航。

3. 账户失败路径和客户生命周期不会伪装成功。
   - clean/dirty logout 首次 DELETE 失败时保留会话并打开可操作的账户弹窗。
   - “保存并退出”和“放弃并退出”均验证：首次 DELETE 500 后可在弹窗内重试，第二次 DELETE 200 后才进入 `/login`。
   - 改密 PUT 失败只在修改密码弹窗显示；关闭后不会把重试动作误执行为 DELETE。
   - 改密要求重新登录时清空 Session、CSRF、Workspace、Query Cache 和密码字段。
   - Mock PATCH 正确更新暂停/恢复状态与版本，不会清空客户名称。
   - 归档 409 在归档弹窗内只显示一个 `role=alert`；重试可操作，请求期间禁止重复提交。

4. 页面布局、键盘和生产边界通过验收。
   - 1440、1280、1024 宽度下整页与客户表格均无横向溢出。
   - 22 个可见交互元素均有可访问名称，无重复 ID。
   - 弹窗焦点、Tab 循环、Escape 关闭和触发按钮焦点恢复通过。
   - 开发界面明确标记 Mock；生产构建不包含 Mock 请求实现、Session 存储键、Mock CSRF 或示例客户数据。
