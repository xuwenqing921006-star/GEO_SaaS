## 业务验收

1. 监测目录包含 10 个国内 P0 / P1 主流 AI 平台；DeepSeek、通义千问标记为 API 自动采样，其余 8 个平台标记为消费者端人工采样。
2. 监测问题必须来自当前客户 P04 已确认且锁定的策略问题；升级前遗留的任意冻结问题集不能绕过批次门禁。
3. `failed`、`not_executed` 和 `succeeded + brand_found=false` 分别表示采样失败、尚未执行、成功回答但未提及，不能互相混算。
4. P07 真实查询最近 30 天指标，并按 API / 消费者端人工两种口径分别显示品牌发现、正确关联、进入推荐、事实准确和核心问题重复出现。
5. 五项指标均显示比率和 `n/N`，并显示明确日期范围、有效样本、失败样本和未执行样本；指标接口失败时不以最新批次冒充时间范围结果。
6. 自动评估的事实准确性与推荐理由有据性默认为待人工核验，不使用模型猜测冒充事实结论。
7. 未发现、错误关联、未推荐、事实错误和采样不足可转换为持久化改进任务。P07 展示任务标题、原因、级别、目标页和时间，并可跳转 P02、P04、P06、P07 继续执行。
8. 系统不包含自动发布，也不承诺一定被平台收录、引用或推荐。

## 指标口径

- 品牌核验问题不进入无品牌问题发现率和推荐率。
- 正确关联率只以已发现品牌的有效回答为分母。
- 事实准确率只以人工完成事实核验的回答为分母。
- 重复出现率只统计同一冻结 P1 问题至少两次成功采样的组。
- API 和消费者端人工样本只在 `mode_breakdown` 内分别计算；两种模式同时存在时，顶层比率及顶层分子、分母均为 `null`。
- 未执行样本没有 `asked_at` 时按 `created_at` 进入时间范围，避免被时间筛选静默丢弃。
