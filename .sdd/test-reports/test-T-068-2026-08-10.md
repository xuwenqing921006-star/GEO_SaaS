## 3. 后端失败用例分析

### 3.1 发布确认旧用例未同步

`test_selected_keywords_create_batch_ai_articles_and_support_publish_archive` 仍在生成任务未确认时直接调用发布接口，当前接口按 T-068 新规则正确返回 `422`：必须先在内容工作台确认本次生成的文章。该失败主要是旧测试流程未同步，不是确认门禁失效，但会阻断持续集成。

### 3.2 搜狐图片要求未在任务提交前完整预检

下列 3 个用例在切换或生成搜狐稿时失败：

- `test_regenerate_document_from_operator_instruction_and_target_channel`
- `test_channel_variants_are_checked_and_exportable`
- `test_content_task_uses_active_keywords_connected_channels_and_balanced_forms`

当前搜狐规则要求至少 1 张正文图片。测试客户没有企业图片时，系统仍先接受生成任务，随后后台任务失败或形成 `partial`，错误为“搜狐号要求至少准备1张正文图片”。

平台规则本身合理，但校验时机不合理：在用户点击生成时就应明确阻止并提示补充图片，或提供合规的系统生成图片方案，不应让任务排队后再部分失败。

1. `t008-p03-p04-real.e2e.ts` 仍寻找“AI 生成首批关键词”，当前关键词页已经改为“确认并生成关键词”。

因此真实页面没有因这两个定位器缺失而不可用，但 E2E 回归门禁仍是红色，必须同步脚本。

## 7. 缺陷清单

### T068-01｜P1｜生产依赖存在已知高风险漏洞

- 前端 `nanoid < 3.3.17` 1 个 High。
- Python `cryptography 49.0.0` 需升级到 50.0.0。
- Python `pypdf 6.14.2` 有 2 个已知漏洞，需升级到 6.15.0。

项目会处理客户上传的 PDF/图片和平台内容，依赖漏洞不应带入发布版本。

### T068-02｜P1｜搜狐缺图未在生成任务提交前阻止

生成请求被接受后才在 Worker 中失败，形成部分失败任务。应把“所选平台所需素材是否齐全”作为同步生成前校验。

### T068-03｜P2｜后端回归套件与 T-068 确认门禁不同步

1 个测试仍绕过任务确认直接发布，导致标准 Pytest 无法全绿。

### T068-04｜P2｜E2E 脚本与关键词、内容工作台新结构不同步

旧按钮和旧标题造成 2/11 失败，当前自动回归不能可靠保护新流程。

### T068-05｜P2｜Ruff 格式门禁未通过

6 个文件需格式化，导致根级完整检查不能全绿。

### T068-06｜BLOCKED｜百家号封面修复后尚未真实复测

代码和单元测试已覆盖百家号 3:2 封面，但现有业务记录仍是修复前上传失败。需要用一篇新的百家号适配稿做一次真实提交，验证上传、审核中、成功/失败回写；本轮未得到真实发布授权范围内的再次确认，因此未执行。

## 8. 数据与安全说明

- PostgreSQL 专项测试使用固定命名的一次性隔离数据库，完成后已精确删除，未接触业务库数据。
- 本轮只读取现有客户、知识、文章、发布和账号状态；没有新增、修改或删除业务数据。
- 未输出 API Key、数据库口令或浏览器会话信息。
- 未触发任何真实平台发布或付费模型调用。

## 9. 结论

T-068 的页面结构和确认后入队逻辑已经基本符合需求，真实页面也没有明显 UI 或运行错误；但项目整体仍有后端回归失败、搜狐素材预检缺口、E2E 过期、格式门禁和依赖漏洞，百家号封面修复后的真实发布也未完成复测。

因此本轮全量验收结论为 **FAIL**。建议修复顺序：依赖漏洞与搜狐前置校验 → 同步后端/E2E 测试 → 格式化 → 使用新文章完成百家号真实发布复测 → 再跑一次全量门禁。
