# T-028 GEO 诊断监测表权限异常

## 期望行为

- 运营人员点击“重新计算诊断”后，后台读取企业事实、内容库存、公开来源和近 30 天
  AI 监测样本，并生成新的诊断结果。
- 没有有效监测样本时应显示“未检测”，不能把没有数据误判成 0 分，也不能让诊断任务失败。

## 实际行为与影响

- 页面返回“任务处理异常，请稍后重试”。
- Worker 在读取 `monitoring_samples` 与 `monitoring_evaluations` 时收到 PostgreSQL
  `InsufficientPrivilegeError`，诊断任务进入失败终态。
- 影响：企业资料、历史诊断和监测数据没有丢失，但运营人员不能重新计算诊断，下游
  关键词与内容建议也无法使用最新诊断快照。
- 严重程度：中，核心数据安全不受影响，但阻断日常诊断操作。

## 根因

- 当前本地 PostgreSQL 数据卷中的监测表归迁移角色所有，但运行角色没有这些历史表的
  `SELECT` 权限。
- 项目已有的角色初始化脚本会为所有现存表补齐 DML 权限，并为迁移角色设置后续新表的
  默认权限；该数据卷在后续迁移完成后没有再次执行权限同步，形成了运行环境漂移。

## 修复

- 重新执行项目自带且可重复运行的 `bootstrap-roles.sh`，统一同步现存表权限和后续默认权限。
- 未扩大运行角色的建表、改表或管理员权限；运行角色仍只有业务表 DML 和序列使用权限。
- 验证 `monitoring_question_sets`、`monitoring_batches`、`monitoring_samples`、
  `monitoring_evaluations` 均可由运行角色读取。
- 验证 `public` schema 中普通业务表缺失 `SELECT` 权限的数量为 0。

## 验证结果

- 修复前真实页面稳定复现异常。
- 修复后最新 `diagnostic` 任务为 `succeeded`、进度 100%、无错误信息。
- GEO 诊断时间更新为 2026-07-29 10:32，页面不再显示异常提示。
- API readiness 为 ready，数据库、存储和 Worker 心跳均正常。
- diagnostics、数据库角色与健康检查定向回归：21 passed。

## 接受标准

1. 当前客户重新计算诊断不再返回“任务处理异常”。
2. 最新诊断任务成功完成，诊断时间与建议更新。
3. 无监测样本继续显示“未检测”，不伪造平台评分。
4. 运行角色拥有监测表所需 DML 权限，但不获得 schema 创建或管理员权限。
