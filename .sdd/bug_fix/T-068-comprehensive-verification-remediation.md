# T-068 综合验收缺陷修复

## 预期行为

- 文章生成任务提交前即完成目标平台和发布素材校验，缺少平台规则或必要图片时同步阻止，不创建必然失败的后台任务。
- 内容生成、确认、文章发布和批量发布的后端测试及真实浏览器流程与当前产品结构一致。
- 前后端格式、类型、测试、构建和生产依赖安全门禁全部可重复通过。

## 实际行为

独立 Tester 在 2026-08-10 的 T-068 验收中发现：搜狐缺少正文图片时仍会先创建后台任务；一个后端发布测试仍绕过确认门禁；两个 Playwright 用例仍使用旧关键词和旧内容工作台结构；六个 Python 文件不符合 Ruff 格式；前端和 Python 生产依赖存在已知高风险漏洞。

## 根因

- 发布平台素材约束只在 Worker 执行阶段校验，没有在生成请求边界复用同一规则。
- 测试脚本没有随“候选关键词确认保存”和“生成任务确认后进入文章发布页”的产品流程同步更新。
- 锁文件仍解析到已披露漏洞的旧依赖版本，格式化门禁此前没有作为收尾检查执行。

## 修复

- 在创建文章批次、渠道版本和按建议重新生成前统一执行平台能力与素材预检；搜狐缺图时返回可执行的 422 提示，不排队、不产生部分失败任务。
- 后端测试先确认生成任务再进入发布，并补充搜狐缺图同步阻止、上传企业图片后恢复生成、渠道版本和回滚的回归覆盖。
- E2E 改为当前“关键词候选确认保存 → 内容生成任务 → 确认文章 → 文章发布页”的完整流程；测试服务固定使用本地发布模拟器，不启动真实渠道浏览器。
- 升级 `cryptography`、`pypdf`，并通过 pnpm override 固定安全版本的 `nanoid`；更新锁文件。
- 修复 Ruff 格式门禁。

## 验证边界

- 本轮未调用付费模型、未执行真实平台发布、未修改生产数据或渠道会话。
- 百家号真实封面上传和外部平台审核回执仍需在独立 Tester 获得明确真实发布授权后验证；本轮只验证代码、平台图片适配单元测试和固定模拟发布闭环。
