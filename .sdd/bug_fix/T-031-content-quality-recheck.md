# T-031 独立模型复核兼容与文章重新质检闭环

## 问题

- DeepSeek 与千问已经返回复核内容，但返回可能使用直接数组、`data/issues` 包装、
  中文风险等级或常见字段别名。
- 原系统只接受唯一且严格的 `findings` JSON 结构，任何字段名差异都会让整次复核
  进入“独立模型复核未完成”。
- 后端已经支持对指定文章版本重新质检，但内容工作台没有操作入口，旧文章无法方便地
  应用升级后的质量规则。

## 目标行为

- 对语义等价且结构常见的复核结果进行规范化，再执行严格的数据校验。
- 对无法识别、缺少问题列表或问题正文为空的结果继续明确报错，不伪造成功。
- 支持单篇和批量重新质检；质检只追加质量记录，不改写标题、正文和历史文章版本。
- 页面展示质检进度，完成后自动刷新文章状态和问题列表。

## 实施边界

- 自动化测试使用固定或模拟模型响应，不调用真实 DeepSeek、千问接口。
- 批量重新质检复用已有的单文章质检任务，每篇文章独立成功或失败。
- 批量范围限定为当前有正文且最新质量状态为“待修正”的文章。
- 知识库更新后需要使用新资料重写正文时，仍应走 AI 重新生成，不通过重新质检静默
  改变文章的冻结事实快照。

## 实施结果

- 复核结果支持直接数组、`data/issues` 等常见包装、中英文问题字段、中文风险等级
  和检查维度别名；规范化后仍通过 Pydantic 严格校验。
- 内容工作台文章行、文章详情和问题修正区域均提供单篇“重新质检”入口。
- 文章列表提供“重新质检待修正文章”批量入口，展示任务进度及最终成功/失败数量。
- 批量操作执行前明确提示会调用独立模型并产生 API 用量。
- 重新质检不新增文章版本、不改写标题和正文；已经发布的当前版本保留“已发布”
  状态，新的质量问题继续通过最新检查记录展示。
- API、Worker 已用新代码重启，健康检查中数据库、存储和 Worker 均正常。
- 自动化验证均使用固定或模拟模型，没有触发真实付费模型调用。
