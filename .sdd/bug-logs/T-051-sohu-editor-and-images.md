# T-051 搜狐号发布编辑器与两张正文图片适配

## 现象

- 搜狐号账号已连接。
- 发布任务提示“搜狐号发布页结构已变化，未找到标题或正文输入区域”。
- 任务没有进入标题、正文、封面和两张企业图片处理步骤。

## 期望

- 自动进入搜狐号文章编辑页，而不是停留在内容管理页。
- 填写标题、正文和摘要，插入两张企业图片并上传文章封面。
- 自动填写摘要；AI 创作声明保持平台页面当前状态，不由系统自动选择。
- 页面结构或图片上传失败时返回具体步骤，不误报发布成功。

## 复现与根因

真实账号只读检查确认，`/contentManagement/first/page` 是内容管理页，页面只有“发布内容”
按钮，没有标题和正文。点击后才进入
`/contentManagement/news/addarticle?contentStatus=1`。旧适配器直接在管理页查找通用输入框，
因此必然失败；同时旧通用流程只尝试一个文件输入框，没有处理搜狐 Quill 正文图片、封面、
摘要、AI 声明和非 button 类型的发布控件。

## 安全边界

- DOM 勘察和回归验证不点击最终发布，不创建公开文章。
- 图片只使用当前文章版本绑定的企业图片，最多两张。
- 正式发布仍以平台成功提示、内容管理记录或公开 URL 为成功依据。

## 修复

- 搜狐号发布改为直接进入真实图文编辑页，不再把内容管理页当作编辑页。
- 增加搜狐号专用标题、Quill 正文、摘要和非 button 发布控件适配；按照产品要求，
  不自动选择“包含 AI 创作内容”。
- 正文上传严格选择文章已绑定的前两张企业图片，并校验编辑器最终新增两张图片；少于
  两张时在点击发布前明确中止。
- 封面继续使用系统生成的文章封面，与两张正文企业图片分开上传。
- 图片弹窗、封面入口、发布按钮或平台校验异常时返回对应步骤，不误报为发布成功。

## 开发侧验证

- `ruff`：通过。
- `mypy app/publishing.py`：通过。
- 搜狐编辑器与发布适配单元测试：14 passed。
- 发布会话、发布前检查及内容发布链路定向回归：18 passed。
- 本地 API readiness：数据库、存储、Worker 心跳均为 `ok`。
- 本地内容工作台只读检查正常，控制台无业务错误。
- 未点击搜狐号最终发布按钮；需由操作者重新执行一次真实发布进行外部平台验收。
